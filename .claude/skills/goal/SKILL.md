# goal · 验收前置的交付模式

一句话：**先把"怎么证明成了"写成可执行的验收，再动手；全绿才算完。**

## 第 1 步 · 定 Goal（人，10 分钟）

在 `docs/goals/<slug>.md` 写：

```markdown
# <一句话目标>

- 日期：<today>
- 状态：running（全绿后改 delivered）

## 验收清单（每条必须可执行或可判定）

- [ ] A1 `curl -s localhost:8181/api/health` 返回 {"status":"ok"...}
- [ ] A2 提问"首末班车"回答含时间区间且标注 FAQ 引用
- [ ] A3 `cd frontend && npm run build` 零错误
- [ ] A4 <观测指标，如：p95 响应 < 3s>

## 不做什么（本期边界）

- <明确排除项，防蔓延>
```

**写不出可量化验收条目 = 需求没想清** → 此时才升档：用 `grill-me` 问透，或走完整流程（intent→spec）。

## 第 2 步 · 干到绿（agent/人，goal 循环）

1. 读 goal 文件，按验收条目顺序实现（每条一个最小改动）
2. 每实现一条立即自验，回执追加到 goal 文件：

```
## 自验回执（<日期>）
- A1 ✅ <实际输出摘要>
- A2 ✅ ...
- A3 ❌ <失败原因> → 修复中
```

3. 有 ❌ 就修，循环到全绿。**禁止**：注释掉测试、放宽验收标准、只挑软柿子捏——验收改不动，改验收=回到第 1 步重新定 goal（人确认）
4. 过程守门照常：local-check → git commit（pre-commit 自动拦密钥/语法）

## 第 3 步 · 交付（人审 ≤5 分钟）

全绿后输出交付包，等人拍板合并：

```
✅ GOAL DELIVERED：<slug>
验收：4/4 全绿（回执见 docs/goals/<slug>.md）
diff：<文件数 / 行数>
一页说明：改了什么 / 怎么验的 / 已知限制 <3 条>
后续：<建议的下一期 goal 或需要升档完整流程的原因>
```

状态改 `delivered`，goal 文件即交付记录（可追溯，无需额外台账）。

## 与完整流程（40 步）的边界

| 走 Goal 模式 | 走完整流程（agent-sdlc） |
|---|---|
| 新功能 0→1、原型、演示 | bug 修复（必须回归用例守门） |
| 验收能写成命令/指标 | 验收难量化（体验类/策略类，需 grill-me） |
| 单人/小队、一次性交付 | 跨模块接口、影响他人契约 |
| 边界清晰的小闭环 | 生产数据变更、对外发布、多人长周期 |

**升档规则**：goal 执行中发现第二个人被牵连、要改公共契约、或验收连续两轮定不出来 → 停止，转完整流程，已产出物并入 intent/spec。
